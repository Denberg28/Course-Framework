# Architecture and decisions

`course_core.py` owns bounded file extraction, syllabus analysis, local template generation, the version-1 project schema, atomic writes, and exports. `engines.py` owns provider adapters using standard-library HTTP. `desktop.py` owns Tk widgets, project lifecycle, worker/result handling, and user review. `app.py` is the optional Streamlit interface.

Desktop state follows **syllabus → request snapshot → pending candidate → explicit acceptance → editable course → save/export**. A single daemon worker performs generation; a bounded queue delivers results to the Tk thread. A failure or discarded response never replaces the accepted course. Editing remains possible during requests. Acceptance restores the source/title snapshot after asking if the source changed meanwhile. API keys are captured in memory for one request and are not part of the allow-listed project schema. No provider SDK, background service, or account database is required.

Project schema: `schema_version` (integer 1), `title`, `syllabus`, `content`, and `engine` (all strings). Unknown fields are discarded on import; unsupported versions and wrong types are rejected before the current project changes. Writes flush a temporary sibling file and replace the target only after completion. Existing contents survive a failed replacement. Users retain history using Save as; no hidden cloud persistence or automatic recovery is implied.

Generation is either deterministic scaffolding with visible content placeholders or API-authored Markdown. AI drafts are not automatically approved teaching materials. Online revisions request a full replacement document, staged for instructor review; the app does not attempt an unsafe automatic merge. Output must finish normally; truncated/blocked results are rejected. Redirects are refused so credentials are not forwarded to a different API host. Error messages omit response bodies, headers, and raw exception text. For custom compatible engines, endpoint/model/authentication remain the user's explicit configuration.

Dependencies: Tk ships with Windows Python; `python-docx` provides Word extraction with body order retained; `pypdf` provides text-PDF extraction. Streamlit is installed only for the web interface/tests and is not bundled into the desktop app. PyInstaller packages the native Windows app. Import parsers run locally; scanned PDFs and complex layouts are not silently interpreted as trustworthy text.

Export HTML intentionally escapes the Markdown source into a printable text view instead of executing HTML or introducing another renderer dependency. The course ZIP uses fixed filenames and includes a reopenable project. Native generated content is editable text, not executable code. Raw HTML is disabled in Streamlit previews.

Baseline reviewed: commit `66f3d9f`, a single-file Streamlit app. It treated every nonempty syllabus line as a module; downloaded content was shown only during the generate-button rerun. A local AppTest reproduced loss of the download widget on the following rerun. No prior test suite, README, CI, or repository AGENTS.md existed. Legacy `temp.txt` is an unused Gemini-era code sample; it is preserved as unrelated history and is not imported or packaged.

`academy_theme.py` centralizes Academy visual tokens and desktop styles. Desktop page navigation uses a persistent left rail backed by the same notebook page container; `<<NotebookTabChanged>>` synchronizes selection after programmatic generation/acceptance transitions. The Streamlit palette shares these values. See [UI alignment](UI_ALIGNMENT.md); this is visual preparation only and adds no Academy dependency, schema migration, or content-publication route.
