# Known issues and validation limits

- **Hosted Gemini secret:** everyone with access to the hosted app can use the configured key’s quota. Access is controlled by the deployment owner. Custom providers never receive this secret.
- **Live AI not validated:** provider tests simulate responses. Preset IDs do not guarantee model/quota access. Generated facts, examples, answers, activity quality, syllabus alignment, and references require instructor review.
- **References:** the bibliography is taken from the syllabus with no automatic agency/publisher additions. It does not provide access to book contents or prove that a reading supports a module. Instructors must check factual claims, page/section details and answer correctness against the actual readings. Missing bibliography entries are marked; supplied URLs are not fetched or independently verified. Model-invented links are flagged. Video recommendations remain excluded. Existing accepted material needs a fresh generation to adopt the new reference policy.
- **Durability:** session memory retains completed modules after a provider failure. Save project before closing/reloading to preserve accepted content and unfinished drafts. There is no autosave or cloud account storage. A crash before saving can lose work.
- **Resume:** requires the same source, title, selected modules, provider, model, and compatible endpoint. Endpoints/keys are not saved; configure them again on reopen. A first-module failure retains an older pending draft and starts fresh on the next attempt.
- **Provider load:** one call per selected module, sequentially; a large course can use up to 80 requests. There is no automatic retry/rate pacing. Quota errors stop the sequence; the user can Resume after resolving quota. Each call uses a socket timeout, not a strict whole-course deadline.
- **Pause:** Windows Pause completes the active request then stops. It cannot reverse provider processing/billing. Streamlit has no in-app pause control; provider failures stop the sequence and allow Resume. Only the last delivered checkpoint is included if saving while a Windows request is active.
- **Project compatibility:** format 1 migrates to 2. Releases before v0.2 cannot open format 2. Keep Markdown exports when reverting. Export course excludes pending work; Save project includes it.
- **Parsing/output limits:** OCR scans and complex/merged tables can need cleanup. AE 416 plain headings and AE 417 field/value curriculum tables support tab/space/pipe copies and Word imports, including leading blank columns and dash/empty hour cells. Space-only copies cannot always recover a missing first hour column; use tabs, pipes or Word to retain column positions. Missing/dash module hours remain unspecified. Old misparsed pending drafts need fresh generation; accepted content is preserved. The parser does not infer week assignments from contact hours. Hour-total mismatches appear in Outline; review allocations before teaching. Limits are 8 MB/file, 100 PDF pages, 180k source characters, 80 detected modules, and 400k characters each for accepted material and rendered pending draft. Split larger courses using selected modules or syllabus sections.
- **Desktop acceptance:** native/package CI and screen captures do not establish manual Windows usability, high-DPI/accessibility, or long-session readiness. Minimum display 1024×768; workspace minimum 940×620. Distribution remains unsigned.
- **Export/integration:** native editing retains Markdown; Windows Preview/HTML exports show the teaching presentation with collapsible assessment/key/reference sections. A collapsed key is not a secure student-exam package. No DOCX/PDF/SCORM export, Academy account integration, or subject publication is implemented. Arbitrary provider-native APIs need adapters; Chat Completions compatibility is required for custom endpoints.

- **Generation speed:** one sequential request per module remains. The original single-call Flash-Lite course generation path was shorter; removing local video suggestions does not remove the multi-request delay. No live latency benchmark is claimed.
- **Legacy pending drafts:** accepted old content is preserved. A fresh draft is needed for the new presentation/MCQ generation format. Offline questions and answer keys remain explicitly incomplete placeholders.

- **Screen verification:** Chromium CI checks actual Streamlit desktop/mobile overflow, navigation, offline generation/download and reduced motion, retaining screenshots for review. Local Chromium downloads were unavailable. Native/browser captures and automated checks do not establish manual screen-reader, high-DPI or OS-specific overlay-scrollbar acceptance. The browser/OS can still control how scrollbars are displayed.
- **Default model:** new sessions/startup and returning to Gemini default to 3.5 Flash-Lite; existing session selections and restored jobs keep their original model. Reload/reboot the app to start fresh defaults. Model availability, quotas and actual latency remain provider-dependent.

- **Scrolling/progress:** the page track is placed below the fixed Streamlit toolbar; Chromium/WebKit gets a contrasting track and minimum thumb, while Firefox/OS rendering can differ. Progress reports completed modules, not token-by-token completion within an active request. A slow first request can correctly remain at 0 completed. Save project still keeps the last successful module checkpoint.
