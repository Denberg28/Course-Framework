# Architecture

`course_core.py` owns extraction, outline parsing, bounded project schemas, atomic writes, and exports. `engines.py` owns HTTPS adapters and module prompts. `course_workflow.py` owns sequential module jobs, resume matching, syllabus-derived reference sections, and draft acceptance. `desktop.py` and `app.py` present the same workflow; `academy_theme.py` owns shared visual tokens.

The user flow is **paste → select agent/scope → Generate → review → Use draft → save/export**. Windows uses a single split workspace. Streamlit restores a vertical, full-width input → controls → materials layout with no workflow tabs, bounded to a 1100 px reading width. Save/Download/Export are above the preview; pending drafts can be downloaded as Markdown without replacing accepted content. Course overview is collapsed so the teaching sequence receives the reading space. File/provider options are secondary; outline review is optional. Manual keys are session-only and provider changes clear manual key/consent. `hosted_keys.py` can read a deployment-owned Gemini key from Streamlit Secrets; it is used only in the Gemini request configuration, never prefilled into widgets or copied into session/project state. A configured deployment key takes precedence over a stale manual Gemini key. Preset model IDs are editable shortcuts, not proof of account availability. There are no background model probes or paid retries.

A generation job snapshots the source, effective title, provider/model, selected indices, a configuration fingerprint, and completed module text. One request generates one module, bounded by the existing output/response limits. The adapter checks provider completion, nonempty/bounded output and credential reflection. The workflow uses lesson_format.py to attach advisory layout notes for discussion/presentation, activity, assessment and A–D/key differences; layout does not reject a completed draft. Before a checkpoint is exposed, the entire pending draft is checked against its character limit. These notes do not establish teaching quality.

After success, a new job dictionary is committed. A failure leaves the prior checkpoint and accepted course intact. Resume requires an exact source/title/selection match and a SHA256 configuration fingerprint (provider, model, compatible endpoint; never the key). A replacement key for the same configuration can resume. An engine/source change begins a new draft; its first failed request does not replace the older pending draft. Full completion is required for acceptance. Acceptance restores the request snapshot; existing accepted material/source changes require explicit replacement approval. Save project keeps both accepted material and the unfinished job; export omits pending work.

Windows has one worker, a bounded result queue, and a pause event. Workers never access Tk. Pause lets the current request finish and queues its result, then prevents a subsequent request. Closing can discard the active request; billing may continue. Saving while busy captures the last checkpoint delivered to Tk, not an in-flight result. Streamlit commits each successful module into session state before requesting another; a provider failure stops the loop and exposes Resume. Save/download is required for durability across application/session loss. No automatic disk or cloud persistence is claimed.

Project format 2 fields: `schema_version`, `title`, `syllabus`, `content`, `engine`, `model`, `accepted_syllabus`, `pending`. The accepted source snapshot keeps course exports consistent even while another syllabus is being edited. The pending allow-list contains only snapshot text, provider/model, a 64-character fingerprint, ascending unique selected indices, and bounded completed text. Imported format 1 migrates to 2. Unknown fields (including keys/endpoints) are discarded. The old schema cannot reopen new projects; Markdown remains portable. Writes flush a temporary sibling and atomically replace the destination.

`reference_catalog.py` now derives its complete reference list from the syllabus bibliography (the filename remains for build compatibility). No built-in agency, university, publisher or subject-based source list remains. `select_references` preserves supplied reading order and assigns SYL source IDs; it does not infer book-to-module support without source text. `reference_context` adds those entries to every provider prompt; deterministic module references append the supplied reading list and require relevance/content confirmation. Missing readings are explicitly marked. Generated hyperlinks are retained only when the URL appears in the supplied bibliography, regardless of domain; unknown links get a verification marker. This is not a crawler, full-text retrieval or citation/factual verification. Video removal remains in new modules. Existing accepted documents are not rewritten.

`lesson_format.py` separates module prose, assessment, answer key, and references for previews. Streamlit renders the latter three as closed expanders. `export_html` renders a safe, standalone teaching presentation with native HTML details; all user/model text is escaped, and only explicit HTTP(S) Markdown links become anchors. There is no script execution or autoplay. Windows Preview writes a temporary HTML file and opens it in the user's browser; the editable native source remains complete Markdown. Collapsing an answer key is a display feature, not exam access control.

HTTPS adapters refuse redirects, keep Gemini credentials in headers, use sanitized errors, bound response sizes, and reject unfinished outputs. Streamlit compatible endpoints require public HTTPS; Windows permits localhost HTTP. This release does not alter authentication protocols or add Aero Academy content/account integration.

The generation module is named `course_workflow.py` to avoid PyInstaller’s third-party `workflow` hook. Native provider details open in a small Settings dialog so expanding them cannot push Generate off a short display.

The teaching-MCQ generation fingerprint separates this contract from earlier drafts. Historical accepted material remains editable; an old incomplete checkpoint starts a fresh draft under the new format. Requests remain sequential, one per module; no live speed improvement is claimed from removing local video suggestions.

Full-syllabus parsing recognizes the plain AE 416 code/title, completion-outcome introduction, units/weekly-hours/standing lines, Textbook and References sections, and LEC HRS/LAB HRS tables. Parsed topic dictionaries optionally carry numeric `lecture_hours`/`lab_hours`; declared totals remain in metadata. Tab, space and pipe copies share the same hour-row handling. Conflicting totals are reported, not rewritten. The original source remains the project/export source of truth. No week schedule is inferred from hours. `course_allocation`/`topic_allocation` share display formatting across drafts and interfaces; the provider prompt receives exact selected-module hours. Supplied readings are the reference basis; there is no automatic source catalog. The generation fingerprint changes for the hour-aware contract; incomplete older jobs require a fresh draft.

The syllabus-reference generation fingerprint starts fresh drafts under this policy. Older accepted material and saved checkpoints remain available for review; unfinished jobs from an earlier contract do not resume as new-policy modules.

`DEFAULT_GEMINI_MODEL` in engines.py is the shared 3.5 Flash-Lite startup default. The ordered preset list includes 3.8 Flash; provider resets use its first entry. Existing Streamlit state and restored pending jobs retain their selected model; the request/profile remains explicit, with no background model switch or new paid retry.

`academy_theme.py` provides static header HTML and scoped page CSS. The original airplane mark, a small inline SVG lesson illustration and local styling need no downloaded images, fonts or scripts. No source/provider text is interpolated into the header. The actual Streamlit main scroll container receives an always-visible vertical scrollbar, stable gutter and smooth anchor scrolling; reduced-motion preferences disable smooth movement. Named Syllabus/Course material anchors and a return link do not alter generation/editor state. The decorative illustration hides on narrow screens. Chromium CI checks actual page navigation, offline generation/download, responsive overflow and reduced motion, and retains desktop/mobile captures separately from native screenshots. Playwright is CI-only tooling and is not a shipped app dependency.

For 0.3.4 the main scrolling viewport starts below Streamlit's 3.75 rem toolbar and is bounded to the remaining dynamic viewport height. Chromium/WebKit uses the pseudo-element scrollbar styling (standard scrollbar color is reset there so it does not override minimum thumb sizing); Firefox retains standard scrollbar colors. The 16 px contrasting track and 56 px minimum WebKit thumb remain visible for long courses. CSS-only injection uses st.html's style event container, avoiding an empty content row.

The Generate callback now only sets a queued flag. In the normal render pass a dedicated status container is placed above the disabled busy action. After all settings/editor widgets are registered, the queued flag is consumed once and generation writes progress into that existing container. Each successful module still commits its checkpoint before the next call. On success/failure a rerun restores the normal button and renders completed/selected counts and the sanitized error/ready text in that same place. Provider/scope/source edits clear display status while preserving checkpoints/accepted content. The session-only progress dictionary contains counts/text/errors, not credentials and not a new project schema.

The browser capture entry point runs the actual app through tools/streamlit_ui_fixture.py, which replaces only the provider transport with delayed test responses and never sends a request. Production continues to run app.py. Browser checks cover both offline export and in-flight simulated generation; no runtime test switches are added to production.

For 0.3.5, table rows are normalized before metadata/section/topic classification. Markdown/Word pipes and clipboard tabs retain empty column positions; field/value labels are joined semantically, and HTML line breaks/entities/nonbreaking spaces are normalized for parsing only. Word extraction wraps rows consistently and keeps cell-internal line breaks inside the row. Hour header indices map numeric cells to lecture/lab even when columns are reversed or empty. Empty/dash module cells remain unspecified rather than borrowing the declared total. Space-only copies use trailing hour values where recoverable. Numbered top-level rows are not demoted solely because the clipboard indents them; plain-text indented subtopics remain supported. Laboratory/Equipment ends the topic section; the bibliography group heading is not a reading. Raw source/project/export text is unchanged. The syllabus-tables-v4 generation profile prevents resuming pre-fix jobs against a different module map; accepted material is not rewritten.

Replacement approval is cleared in the Generate callback, before widget registration. Clearing its checkbox key inside the generation loop after the page widgets render raises a Streamlit state error when an earlier draft/accepted course is present; callback-time reset keeps the replacement gate safe and permits all requested modules to finish.

For 0.3.6, engines.py owns the canonical GEMINI_FLASH_MODEL ID and gemini_request_settings. The exact 3.8 preset (also with the models/ prefix) explicitly sends thinkingConfig.thinkingLevel medium with maxOutputTokens 32768, and passes a 180-second timeout into request_json. Lite/custom Gemini and compatible APIs retain 60-second timeouts and prior output limits; custom model capabilities are not guessed. The transport injection remains a three-argument contract; production request_json accepts a keyword timeout. HTTP/no-redirect/TLS/bounded-response protections remain. Known finish-reason labels and sanitized transport errors distinguish limit exhaustion, content filtering, recitation, continuation, network failure and server timeout/unavailability. No provider body, finishMessage or unknown status string is surfaced. Non-STOP material is never checkpointed. The teaching/parser contract and schema are unchanged, allowing matching unfinished jobs to resume with new transport settings. Test fixtures accept the timeout keyword and verify 3.8 payload/timeout; no real provider call occurs in CI.

For 0.3.7, Generate is disabled only while a request is queued/running. The previous server-derived count can remain zero while a pasted textarea still has focus, so using that count to disable the submit action creates a dead end until blur/Ctrl+Enter. Keeping the action enabled lets its click submit the updated source along with consent/settings; the normal render parses the new source and executes the queued job once. Empty input is rejected before configuration/consent checks with an inline paste instruction and no transport call. Existing online-consent checks and busy/no-repeat behavior remain. No widget is programmatically auto-consented and no provider is called just by editing text.

For 0.3.8, an unlabelled title immediately followed by numbered/bulleted/Week topics is treated as a course heading, and numbered/bulleted rows after metadata start topics without requiring a section label. Plain course-code inference is limited to uppercase codes so mixed/lowercase subjects such as drone 101 are not consumed as metadata. If only a meaningful title/description is supplied, the parser creates one topic; a single plain topic also supplies its course title. Course fields, references, hours and outcomes stay optional. No supplied metadata, hours or references are invented. The provider is asked to propose draft objectives when outcomes are absent. The module-input-v5 profile prevents old parser/prompt jobs resuming against a changed interpretation. Original/accepted content remains available.

validate_lesson remains a strict lint helper for review tests; generation does not call it as an acceptance gate. lesson_review_notes converts a layout finding to an advisory note, appended once by the workflow after source-link/video cleanup. Brief or differently headed completed content is retained, including content that would otherwise be removed as a standalone top heading. The provider completion/nonempty/credential and size guards remain hard checks. Offline output stays an explicit placeholder framework. See MODULE_POLICY.md.
