# Module creation policy

Create a reviewable draft from the input the instructor has. A formal syllabus is optional.

- Accept a single topic, a course title with a short numbered/bulleted list, an existing outline, or a full syllabus.
- A title followed by topics names the course; each listed topic becomes a module. A title/topic alone creates one module. Do not require Week or Topics labels.
- Missing course codes, learning outcomes, contact hours and references do not prevent generation. Propose draft learning objectives when none are supplied; keep unspecified schedules/hours unassigned.
- Request discussion/presentation, an example, an activity, five A–D MCQs and a letter key. If a completed response uses another layout or omits a requested part, keep the draft and add a review note. Do not issue automatic paid retries just to fix formatting.
- Use supplied references when present. When absent, draft general subject explanations and mark references as not supplied; never invent a bibliography, source access, page numbers or institutional requirements.
- Stage completed modules for review. Preserve accepted material until the instructor chooses Use draft and approves replacement when required.
- Keep the existing key/online-consent controls. Empty input, provider/network failures, truncated responses, credential reflection and file/output size limits remain guarded. Preserve earlier successful modules when a later request fails.
- Offline mode creates editable placeholders; it does not invent teaching facts or correct quiz answers.

Example input:

```text
drone 101
1. drone component
2. drone schematic
```

Result: course **drone 101**, Module 1 **drone component**, Module 2 **drone schematic**. Outcomes, hours and references can be added later.

Formatting notes and successful generation do not certify factual accuracy. The instructor reviews the draft before teaching.
